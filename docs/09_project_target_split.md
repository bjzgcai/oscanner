OScanner 功能聚焦讨论

现在 OScanner 里有多个功能点，职责是不清晰的，每个工具应该只做自己的事情，不要加入其他工具的功能，类似 Unix 的工具。 

我们的目的是考察一个软件工程师在各方面的能力。这个能力的描述在 https://gitee.com/zgcai/oscanner/blob/main/engineer_level.md，  这是 OScanner 的最主要功能，每一个 “扫描 scan”， 或者 “检查 check” 是专注于一个数据来源。 
1） 基于工程师写的代码的实际运行情况和功能 spec 的对比， 这就是功能测试，validation。
2）基于 git commit 中的代码质量分析，verification。
3）基于工程师做 PQ 问答的题目的成绩 （相当于面试或者考试的成绩）
4）其他 (例如， leetcode 测试的成绩） ... 

OScanner 的每个子功能获得了这些数据， 要把数据持久化， 用下面的格式：
扫描对象-用户，  扫描方式， 扫描时间，扫描的分数， 扫描结果的文字说明（可以是 AI 生成）... 


从宏观来看：   我们有下面几类实体：
工程师
工程师产生了能力数据的原始数据 - 工程师做项目或者做编程测试，回答问题等， 产生了反映其能力的各种源数据  （能力数据的生产者）
Oscanner - 能分析源数据，并产生了评价数据， 用户能力评价数据的生产者， 是 OScanner 
数据库 - 是用户能力评价数据的储存地点
可视化工具 -  各种可视化工具可以读取这些能力评价数据， 做出各种可视化， 它是数据的消费者。 

我们可以把一个工程师的所有公开的源数据都一起分析，得出这个工程师的总体能力，  也可以跟踪他的不同时间点， 得出他在不同时期的不同能力。 


在这几类实体之外， 我们还有一个教学活动 --  一门公开的课程。 

老师讲授课程， 并发布工作的 assignment， 有一定的 deadline
学生学习课程， 并按时完成 assignment， 他们提供了 “源数据”， 绝大部分是 repo 的commit， 和 PQ 的成绩证据。 

老师根据assignment 的时间点， 从注册课程开始，所有学生从 0 开始， 然后每个 assignment 的检查点，获得出不同学生的得分，  用可视化工具画出了各种千帆竞发图， 这是管理这门课程的一个手段。

## 数据生产者
三个独立的工具：以用户为key，跑不同的子工具，往数据库里吐用户的不同类型评测的数据

* 成长轨迹
	* checker：对标的是 agent 开发里的 tools 的能力
* 测试运行器+PQ
* 数据生产工具

设计 <工具，用户> -> 通用数据结构

## 用户数据的展示

* 千帆竞发（读数据可视化）
	* 这个是和具体工具以及课程应该解除耦合的，课程能用，任意一组仓库repo通过工具产生的数据也应该能用
	* 复用之前的工具，约定好输入输出数据格式（需要一个数据格式文档放 docs 目录下）

## 结论：OScanner 目标聚焦

1. 只做扫描，和其他工具的集成，应该是另外一个事情（PQ和千帆竞发不应该在这里展示）
2. OScaner的数据只关心自己的数据写数据库，数据怎么消费是其他工具的事情
3. 课程也是自己独立的数据
